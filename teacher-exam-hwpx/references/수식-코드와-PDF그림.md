# 수식·코드와 PDF 그림

## 숫자와 수식

시험 날짜·문항 번호·배점은 문서 관리용 텍스트로 둔다. 문제의 수량·단위·관계식·분수·첨자·화학식은 한글의 편집 가능한 수식 개체로 넣는다. 제공 PDF에서 발췌한 그림 내부의 숫자·축·범례는 그림 원본을 보존한다. 코드 안 숫자와 연산자는 실행 문법의 일부이므로 코드 문자로 유지한다.

`hancom_fill.ps1`의 문단은 `text` 또는 순서 있는 `runs`로 입력한다. `runs`를 사용하면 일반 문장과 수식 개체가 같은 문단에 들어간다. 검토할 원문은 `text`에도 남기되 실제 입력에는 `runs`만 사용한다. 글자 크기는 현재 양식의 본문을 읽어 맞춘다.

```json
{"style_id":0,"text":"질량은 0.2 kg이다.","runs":[
  {"kind":"text","text":"질량은 "},
  {"kind":"equation","script":"0.2~rm kg","base_pt":11},
  {"kind":"text","text":"이다."}
]}
```

한글 수식 스크립트 예: `Q = c m DELTA T`, `c_P = c_R`, `{a+b} over c`, `20~DEG rm C`, `rm {H_2 O}`. 외부 LaTeX를 이 문자열에 그대로 넣지 않는다. 실제 HWPX의 `equation` 개수·스크립트·크기를 원고와 대조하고 PDF에서 분수선·첨자·그리스 문자·단위의 모양을 확인한다. 지원하지 않는 수식은 일반 텍스트로 바꾸지 말고 그 항목을 알린다.

코드와 여러 답안 조건의 상자 배치는 [해설·조건 상자와 코드](해설-조건상자와-코드.md)를 따른다. 발췌 쪽수·해시는 검수 기록에 남기며 시험지에 제작 안내를 자동으로 덧붙이지 않는다.

## 알고리즘과 코드

코드는 문법과 들여쓰기를 보존한 텍스트로 넣는다. 한 줄을 한 문단으로 만들고 `code: true`를 붙인다. 도구는 현재 문단 스타일을 복제한 코드 전용 스타일을 작업 사본에만 추가하고, 영문을 Consolas 등폭 글꼴로 쓴다. 기존 글꼴·문단·스타일을 바꾸지 않는다. 코드가 아닌 단락은 기존 스타일로 돌아간다. 줄이 넘어가면 문법적으로 안전한 분할이나 배치를 먼저 조정하며 들여쓰기를 줄여 맞추지 않는다.

```json
{"style_id":0,"code":true,"text":"for x in data:"}
{"style_id":0,"code":true,"text":"    if x >= 0:"}
{"style_id":0,"code":true,"text":"        result.append(x)"}
```

실제로 실행할 수 있는 언어라면 허용된 로컬 환경에서 대표 입력·경계 입력·반례를 실행한다. 원본 목록 보존, 0·음수, 같은 값의 반복, 첫째·마지막 항목, 종료 뒤의 입력을 문제에 맞게 확인한다. 한글에 저장된 각 줄의 공백·기호가 원고와 같은지 확인하고, PDF에서 들여쓰기와 줄 묶음을 읽는다. 이미지로 만든 코드는 편집 가능한 코드 검증을 대신하지 못한다.

## 교사가 준 PDF에서 필요한 그림만 발췌

다른 스킬이나 그림 제작 엔진을 설치하지 않는다. Windows PowerShell의 `scripts/pdf_crop.ps1`은 Windows 내장 PDF 렌더링과 .NET 이미지를 사용한다. Windows PowerShell 5의 `powershell` 명령으로 실행한다. 원본과 기존 출력을 덮어쓰지 않는다.

1. PDF의 문항·캡션·쪽수를 살펴 필요한 그림의 위치를 찾는다. 원본 PDF 해시와 실제 PDF 쪽수(첫 쪽은 1)를 기록한다. 페이지에 인쇄된 쪽수와 PDF 쪽수를 구별한다.
2. 후보 쪽만 PNG로 렌더링해 직접 본다. 원본이 스캔이거나 그림 위치가 모호해도 보지 않고 좌표를 추측하지 않는다. 전체 페이지 PNG는 확인용으로만 둔다.
3. AI가 그림의 왼쪽·위·오른쪽·아래를 정한다. 좌표는 전체 페이지 폭·높이를 1로 보는 0~1 값이다. 축·단위·범례·화살표·필요한 기호와 패널을 포함하고 다른 문항·정답·해설은 제외한다. 그림 밖의 조건이 필요하면 그 조건을 별도 본문으로 정확히 옮긴다.
4. 해당 영역만 새 PNG로 잘라 직접 본다. 원본의 해당 영역과 글자·선·숫자·필수 라벨을 대조한다. 흐리거나 잘렸으면 영역과 해상도를 고쳐 새 캡처를 만든다. 캡처로 사라진 근거를 AI가 채워 넣지 않는다.
5. 문항에는 캡처 파일만 문서에 포함하여 넣고 가로세로 비율을 유지한다. 실제 인쇄 크기에서 라벨을 읽는다. 원본 PDF·쪽수·영역·출력 해시를 검토 기록과 연결한다.

```powershell
# 후보 쪽을 보는 용도
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pdf_crop.ps1 -Source 교사자료.pdf -Page 2 -Dpi 120 -Output work/page-2.png
# 실제 좌표는 렌더링한 쪽을 보고 AI가 정한다. 아래 수치는 문법 예이다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pdf_crop.ps1 -Source 교사자료.pdf -Page 2 -Region "0.12,0.18,0.88,0.53" -Output work/figure.png -Receipt work/figure.json
```

PDF 렌더링 요청 해상도와 실제 출력 픽셀 수는 기록에서 확인한다. 실제 인쇄 해상도는 캡처 픽셀 수와 한글에서의 인쇄 폭으로 판단한다. 필요한 영역을 크게 렌더링해도 원본에 없던 세부 정보는 생기지 않는다. 암호·접근 제한으로 읽을 수 없는 PDF는 우회하지 말고 읽을 수 있는 자료를 요청한다.

그림 문단의 명세는 다음과 같다. `path`는 실제로 확인한 파일의 절대 경로다. `sha256`이 다르면 입력을 중단한다. 크기는 현재 단 폭에 맞춘 실제 mm 값이며 기본값을 임의로 다른 학교 양식에 대입하지 않는다.

```json
{"style_id":0,"text":"","image":{
  "path":"그림 파일의 절대 경로.png","sha256":"확인한 SHA-256",
  "width_mm":98,"height_mm":58
}}
```

수식·코드·그림 입력 뒤 최종 HWPX에서 직접 PDF를 출력한다. 모든 수식이 개체로 남고, 코드는 문자로 남으며, 문서 내부에 원본 캡처가 포함됐는지 확인한다. 필요한 그림을 별도 창에서 본 사실만으로 문항 안에 들어갔다고 보고하지 않는다.
