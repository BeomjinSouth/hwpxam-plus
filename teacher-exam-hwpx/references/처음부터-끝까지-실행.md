# 한 요청으로 제작하는 실행 절차

교사는 양식·자료와 출제 조건을 주고 스킬을 호출한다. 다음 입력 파일 작성과 실행·수정·검수는 AI가 맡는다. 이전 채팅, 작업 폴더의 개인 스크립트, 이미 만든 시험지나 미리 만든 교사용 기준본을 요구하지 않는다. 실행 중 문제를 발견하면 원고 또는 위치표를 고쳐 다시 출력한다. PDF만 따로 고치지 않는다.

## 1. 원본을 확인하고 위치표를 만든다

`scripts/exam_pipeline.py`가 전체 실행 도구이다. Python 3.10 이상 표준 라이브러리와 Windows에 설치된 한글을 사용한다. 추가 Python 패키지는 필요 없다. 한글을 제어하기 전에 현재 환경에 적용되는 점유·보안 규칙을 따른다.

HWP라면 먼저 `hancom_fill.ps1`에 Spec 없이 새 HWPX 경로를 주어 변환한다. HWPX는 그대로 구조를 읽는다. `inspect` 결과와 원본 PDF를 함께 보고 본문 시작·끝, 제목, 스타일을 확인한다. 파일마다 위치가 다르므로 예제의 숫자를 복사하지 않는다.

```text
python -B scripts/exam_pipeline.py inspect 제공양식.hwpx
```

`양식위치.json`의 구조는 다음과 같다. `source_sha256`은 prepare에 넣는 실제 파일의 해시이다. HWP를 제공했다면 변환 사본이 아닌 원래 HWP의 해시를 쓴다. start/end와 teacher_keep은 같은 파일을 한글로 저장한 뒤 확인한 최상위 문단의 0부터 시작하는 인덱스이다. 여러 구역을 가로지르거나 표 안에 있는 본문은 자동 처리 범위를 벗어나므로 임의 삭제하지 않는다.

```json
{
  "source_sha256": "확인한 원본 해시",
  "section": "Contents/section0.xml",
  "body": {"start": 13, "end": 13, "expected_start_text":"{{BODY}}"},
  "body_range_reason": "본문 표시자 문단이며 앞뒤 제목과 확인란은 고정 영역임을 확인함",
  "teacher_keep": [12],
  "teacher_layout_reason": "교사용은 동일 용지·제목·다단을 사용하고 학생용 표지와 주의사항을 생략함",
  "box_width_mm": 105,
  "styles": {"body": 0, "passage": 11, "mc": 3, "essay": 4, "choice": 6}
}
```

교사가 교사용 양식을 따로 주면 그 양식을 우선한다. 자동 준비는 학생용 양식의 용지·구역 설정과 확인한 제목 문단을 재사용한다. 제목이 첫 문단의 표 안에만 있거나 자동 범위로 분리할 수 없으면 그 한계를 알리고 원본 개체를 보존할 대안을 마련한다. 새로운 학교 양식을 설계하지 않는다.

```text
python -B scripts/exam_pipeline.py prepare --source 제공양식.hwpx --layout 양식위치.json --out 준비양식
```

이 명령은 원본의 전체 쪽 배치를 계산한 뒤 저장해 구조와 실제 표시 높이를 읽는다. 내용에 맞춰 자동으로 늘어난 고정 안내 표가 짧은 시험정보 입력으로 줄어들지 않도록, 한 셀짜리 고정 표의 원본 표시 높이를 복제 기준의 최소 높이로 유지하고 기록한다. 원본 파일·글꼴·표 폭·선은 바꾸지 않는다. 본문 앞 고정 문단의 실제 줄 위치와 높이가 원본과 같아야 준비를 통과한다.

지정한 본문만 비우고 학생용·교사용 기준본과 PDF를 만든다. 교사용에는 해설 본문·항목 스타일을 원래 본문에서 복제하여 추가한다. 기존 스타일은 바꾸지 않는다. 두 기준 PDF의 고정 영역을 확인한 뒤 다음 단계로 간다. 인덱스나 스타일을 추측하여 실행하지 않는다. 여러 행의 자동 높이 표 등 현재 처리로 원래 배치를 유지하지 못하는 양식은 실패로 보고하며, 임의로 행 높이를 배분하지 않는다.

## 2. 한 원고에서 인쇄 구조를 지정한다

[원고 형식](원고-형식.md)의 검토 필드를 모두 작성한다. 중상 문항은 [문항 제작 요령](문항-설계와-검토.md)의 후보 비교·우회 점검·탈락 기준을 적용한다. 도구 검사에 맞춰 근거를 꾸며 채우지 않는다.

각 문항에 `presentation.student`를 둔다. 첫 문단은 `question`이며 다음은 `body`, `passage`, `condition`, `code`, `image` 중에서 고른다. 이미지 외 모든 text를 줄바꿈으로 연결한 값이 원고의 `stem`과 정확히 같아야 한다. 자료·조건을 두 번 쓰지 않는다. 문항 번호와 배점은 도구가 붙인다. 선택지는 원고의 choices에서 자동으로 넣는다.

```json
{
  "presentation": {
    "student": [
      {"kind":"question", "text":"자료를 근거로 다음 조건에 맞게 설명하시오."},
      {"kind":"passage", "text":"실제 판단에 필요한 제시 자료"},
      {"kind":"condition", "text":"두 자료의 차이를 설명할 것"},
      {"kind":"condition", "text":"자료로 뒷받침할 수 있는 결론을 쓸 것"}
    ],
    "answer_lines": 5,
    "break_before": "column",
    "teacher_break_before": "column"
  }
}
```

연속하는 passage·condition·code는 종류별 상자로 묶고, 앞에 기존 스타일의 빈 문단을 넣어 발문·상자가 붙지 않게 한다. 같은 종류의 상자가 둘이면 `group`에 서로 다른 짧은 ID를 준다. `caption`으로 짧은 제목을 지정할 수 있다. 코드의 한 줄은 하나의 code 문단이며 들여쓰기를 보존한다. 코드 제목 폭도 자동으로 확보한다. 위치표의 box_width_mm에는 양식의 실제 본문 한 단에 들어가는 폭을 확인해 넣는다. 상자 폭과 병합 셀을 함께 맞추고 원형의 선·여백을 보존한다. 도구는 제공된 상자 원형을 복제하며 PDF 위에 테두리를 덧그리지 않는다.

수식이 있는 문단은 `runs`로 text/equation을 지정한다. 원고의 `rich_text`에 정확한 문단 문자열을 키로, runs 배열을 값으로 두면 학생용·교사용의 같은 문장을 함께 처리한다. 과학·수학의 수량·단위·변수도 수식 개체로 입력한다. 코드의 숫자와 기호는 코드 문자로 유지한다. 자동 문자열 추측으로 과학식이나 코드를 수식으로 바꾸지 않는다.

그림은 image 문단의 `image`에 절대 경로·sha256·width_mm·height_mm를 둔다. `text`는 빈 문자열이다. 제공 PDF를 먼저 읽고 필요한 그림의 쪽과 영역을 AI가 정한 후 `pdf_crop.ps1`로 발췌한다. 축·범례·단위를 포함하고 문제·해설·다른 그림은 제외한다. 원본 PDF·발췌본을 대조하고 문항의 실제 판단에 그림이 쓰이는지 확인한다.

교사용 정답·풀이·모든 보기 해설·루브릭·인정 답안·부분점수·답만 쓴 경우는 원고에서 자동으로 구성한다. 코드가 들어간 정답이나 해설은 `presentation.answer` 또는 `presentation.derivation`에 같은 종류의 문단 배열로 둔다. text를 연결한 값은 각각 원고의 answer, derivation과 정확히 같아야 한다. 내부 문항 ID·출처 확인 메모·예상 난도·제작 안내는 인쇄 본문에 넣지 않는다.

`metadata.student`와 `metadata.teacher`에 실제 원문에서 바꿀 문자열을 키로, 새 값을 값으로 적는다. 예를 들어 `"{{EXAM_TITLE}}":"과학 정기시험"`과 `"수     학":"과     학"`을 넣는다. 원문에 없는 키는 적용되지 않는다. 원문의 남은 표시자는 실패한다. 날짜·과목코드·학교명·출제자 등은 제공한 정보만 사용한다. 검증용 가상 정보는 교사 요청이 있을 때만 사용하고 실제 원본의 개인정보는 새 문서에 남기지 않는다.

실제 상자 안의 자료·조건은 기존의 테두리 없는 `styles.body`를 재사용한다. 테두리가 있는 지문 스타일을 표 안에 중복 적용하지 않는다. 원본 스타일 정의는 수정하지 않는다. `styles.body`에 테두리가 있으면 위치표에서 확인한 기존의 테두리 없는 스타일을 지정한다.

## 3. 출력·대조·시각 검수를 끝낸다

`run`은 역할별 `학생용-시험정보기준.hwpx/pdf`, `교사용-시험정보기준.hwpx/pdf`도 자동 생성한다. 원래 기준 양식에 승인된 replacements만 적용하고 본문은 넣지 않은 파일이다. 실행결과의 `authorized_fields_baseline`에 경로·해시·쪽수를 남기며 `render`는 이 기준본의 전 쪽도 `fields-baseline` 이름으로 렌더링한다. 원본 표시자가 긴 경우 실제 시험정보 입력만으로 줄바꿈과 집계 높이가 달라질 수 있으므로, 원본→시험정보 기준→최종의 차이를 나누어 확인한다. 원본 구조 비교는 계속 유지하며 이 기준본으로 차이를 숨기지 않는다. 고정 표·셀·글꼴 속성을 대조하고, 표지와 제목 등 본문 밖 실제 선 경계를 비교한 근거를 `fixed_geometry_proof`에 연결한다. 선 경계가 다르면 PASS로 해제하지 않는다.

```text
python -B scripts/exam_pipeline.py run --content 원고.json --layout 양식위치.json --templates 준비양식 --out 결과
python -B scripts/exam_pipeline.py render --receipt 결과/실행결과.json --out 결과/쪽별미리보기
```

run은 원고 검사 → 학생·교사 명세 작성 → 편집 가능한 한글 입력 → 실제 상자 복제 → 같은 문서의 PDF 출력 → 최종 상자 안팎의 문장·수식·코드 일치 → 고정 양식과 본문 앞 실제 줄 배치 대조를 수행한다. 시험정보만 채운 기준본이 최종본과 같아도 원래 양식에서 고정 영역이 이동했다면 통과하지 않는다. 원본→복제 기준→최종본의 관계를 확인한다. `{{PAGES}}`에 적은 쪽수가 실제와 다르면 정보를 고쳐 다시 출력한다.

오류가 나면 중단한다. 결과 폴더는 새 이름을 사용하며 기존 파일을 덮어쓰지 않는다. 원고를 고치면 전체 출력과 관련 검수를 다시 한다.

render는 최종 PDF의 모든 쪽을 PNG로 만든다. AI가 각 쪽을 열어 잘림·겹침·여백·상자 간격·코드 줄바꿈·수식·그림·답안 공간·교사용 배열을 확인한다. 원고만 확인하고 PDF 검수를 통과시키지 않는다. 학생용을 다시 풀어 선택지 정오와 채점기준도 대조한다.

`검수.json`에는 다음을 기록한다. 각 쪽의 evidence는 실제로 본 배치와 발견·수정 여부를 짧게 적는다. 한글의 표 높이 캐시만 달라져 `NATIVE_LAYOUT_REVIEW_REQUIRED`이면 원본·최종 PDF의 고정 선 위치를 비교한 자료 경로·해시·판단을 `fixed_geometry_proof`로 추가한다. 단순히 '확인함'으로 해제하지 않는다.

```json
{
  "receipt_sha256":"실행결과.json의 해시",
  "student":{"pages":[{"page":1,"pdf_sha256":"현재 학생용 PDF 해시","status":"PASS","evidence":"실제 쪽을 보고 확인한 내용"}]},
  "teacher":{"pages":[{"page":1,"pdf_sha256":"현재 교사용 PDF 해시","status":"PASS","evidence":"실제 쪽을 보고 확인한 내용"}]},
  "item_review":[{"id":"문항 ID","answer_check":"학생용으로 다시 푼 결과","difficulty_check":"필요한 판단과 발견한 우회로","rubric_check":"문항 요구와 배점·인정 답안 대조"}],
  "limits":["실제 교과서 대조·학생 반응 검증 등 하지 못한 범위"]
}
```

```text
python -B scripts/exam_pipeline.py finalize --receipt 결과/실행결과.json --review 검수.json --out 결과/최종검증.json
```

finalize는 현재 파일 해시와 전 쪽 검수 기록을 확인한다. 문항별 검토가 실제로 수행됐는지는 AI가 근거로 책임진다. 최종 상태가 있어도 학교 교육과정 적합성·실제 난도 통계를 자동으로 증명하지 않는다. 최종 HWPX/PDF와 짧은 검증 범위만 전달하고 제작 중 메타 설명은 시험지에 싣지 않는다.
