# 양식 보존과 실행

## 원본과 변경 범위를 먼저 고정한다

원본의 절대 경로·SHA-256을 기록하고 사본에만 쓴다. `.hwp`는 설치된 한글로 `.hwpx` 사본을 내보낸 뒤 기준 파일로 삼는다. 변환 전 원본도 보존하며 변환 PDF와 쪽수를 대조한다. PDF·이미지만 있다면 편집 가능한 원본을 요청하고 같은 구조를 보존했다고 주장하지 않는다.

한글의 무편집 저장에서도 사용하지 않는 서식의 제거와 내부 ID 재정렬이 생길 수 있다. 내용 수정 전에 `hancom_fill.ps1`을 `-Spec` 없이 실행하여 한글 무편집 저장본과 PDF를 만든다. 원본과 무편집 저장본의 화면을 비교하고, 그 저장본을 내용 입력과 구조 비교의 기준으로 사용한다. 원본·기준 저장본의 연결은 실행 기록의 해시로 남긴다. 숫자 ID가 바뀌었을 때는 실제 글꼴·서식 연결이 보존되는지 대조하며 다른 서식으로 재작성하지 않는다.

`python scripts/exam_check.py inspect "기준양식.hwpx"`로 용지·다단·표·본문·스타일·필드와 현재 텍스트를 읽는다. 이 명령은 읽기 전용이다. 기존 예시 문항·메모·정답 표시가 있는지 확인한다. 채울 위치는 기존 표시자 또는 명확히 지정한 기존 문자열로 특정한다. 반복 문구를 전역 치환할 때에는 모든 발생 위치가 승인된 내용인지 확인한다.

설치된 스킬 폴더를 현재 폴더로 가정하지 말고 실제 스킬 위치에서 명령의 절대 경로를 구한다. 결과는 교사의 작업 폴더에 둔다.

## 실행 환경

- 설치: PowerShell 기본 기능. 다른 프로그램이나 계정 등록이 필요 없다.
- 한글 열기·변환·내용 입력·PDF 출력: Windows와 설치된 한컴오피스 한글의 `HWPFrame.HwpObject` COM. PowerShell이 직접 호출하므로 pywin32가 필요 없다.
- 원고·구조 검사: Python 3.10 이상 표준 라이브러리. 기존 Python이나 AI 도구가 제공하는 실행 환경을 먼저 찾는다.
- Mac·Linux 또는 한글이 없는 환경: 원고·내용 검토·HWPX 읽기만 가능하다. 외부 서비스에 시험지를 업로드하거나 프로그램을 자동 설치하지 않는다.

이미 등록된 한글 보안 모듈이 있으면 사용한다. 별도 모듈은 필수 조건이 아니다. 미등록이면 새 한글 창에 표시되는 파일 접근 확인을 사용자가 허용해야 한다. 보안 설정·레지스트리·실행 정책을 영구 변경하거나 DLL을 설치하지 않는다. 실제 데스크톱 제어가 필요할 때에는 해당 환경의 컴퓨터 사용 지침과 점유 규칙을 따른다. 새 자동화 객체만 사용하고 사용자가 열어 둔 문서는 건드리지 않는다.

## 명세 파일

`hancom_fill.ps1`은 다음 JSON을 받는다. 예시는 문법 설명이며 실제 양식의 문자열·스타일로 바꾼다. `source_sha256`은 기준 양식의 실제 해시다. `replacements`는 지정된 시험 정보만 바꾸며, 머리말·꼬리말·표 안을 포함한 양식 전체에서 `count`와 실제 발생 수가 다르면 중단한다. 이 단계는 ZIP 사본의 원래 XML·런·개체를 보존한 채 지정된 텍스트 조각만 바꾸고 변경한 구역의 오래된 줄배치 캐시만 제거한다. 여러 런에 걸친 치환은 멈추고 해당 부분을 네이티브 편집으로 처리한다. `body`는 본문 위치 하나에 기존 스타일로 문단을 채운다. 본문을 이미 채운 양식이면 쓰지 않는다.

```json
{
  "source_sha256": "이번 원본의 SHA-256",
  "replacements": [
    {"find": "{{SUBJECT}}", "replace": "국어", "count": 2}
  ],
  "body": {
    "anchor": "{{BODY}}",
    "blocks": [
      {"text": "문항 본문 [5점]", "style_id": 3},
      {"text": "① 첫째 보기", "style_id": 9}
    ]
  }
}
```

`style_id`는 예시의 숫자를 복사하지 말고 현재 양식에서 읽는다. 모든 block에 기존 스타일의 정수 ID를 명시하며 도구가 실제 존재 여부를 확인한다. 문단마다 block을 나누고 text 안에 줄바꿈을 넣지 않는다. 기존 자동 번호 스타일을 쓸 때에는 문항 번호를 문자열로 다시 쓰지 않는다. 선택지에 필요한 탭·문단 구조를 유지한다. `break_before`는 기존 본문의 단·쪽 배치가 허용하는 경우에만 `column` 또는 `page`로 쓸 수 있다. 표·글상자 내부의 본문 채우기는 실제 위치와 개체 잠금을 별도 확인하고 네이티브 편집으로 처리한다. 현재의 엄격 비교 도구가 다루는 자동 본문 삽입은 표 밖의 단일 본문 표시자이다.

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/hancom_fill.ps1 -Source "양식.hwpx" -Output "학생용.hwpx" -Spec "채움명세.json" -Pdf "학생용.pdf" -Receipt "한글실행.json"
```

변환·출력만 할 때에는 `-Spec`을 생략한다. 원본과 같은 경로 또는 기존 결과 파일에는 저장하지 않는다. 실패하면 미완성 파일을 완성본으로 전달하지 않고 원본 사본에서 원인을 고쳐 다시 시작한다.

## 양식 보존 검사

`python scripts/exam_check.py compare "기준.hwpx" "학생용.hwpx" --plan "채움명세.json"`으로 용지·다단·기존 표·셀 규격·스타일과 번호 정의·첨부 바이너리, 지정 본문 밖 문단의 내용과 서식 적용을 비교한다. 추가 본문 문단은 허용하되 고정 구조와 기존 서식의 차이는 실패로 남긴다. `--plan`이 없으면 본문 밖 문단 내용과 적용 서식은 대조하지 않으므로 양식 보존 완료 근거로 쓰지 않는다. 이 비교는 새 본문 내용 일치·줄바꿈·실제 인쇄 모양을 증명하지 않는다. 원본과 최종 PDF를 함께 보고 글꼴·간격·쪽 구성을 확인한다.

본문 배치를 맞추려고 원본에 없는 스타일·번호 체계를 만들지 않는다. 코드가 포함된 경우에는 예외적으로 기존 스타일을 복제한 코드 전용 스타일과 등폭 영문 글꼴만 사본에 추가한다. 기존 스타일은 그대로 두며 번호 체계는 추가하지 않는다. 고정 영역과 본문 흐름의 차이를 구별하고, 공간 부족이나 지원하지 않는 양식은 필요한 변경을 교사에게 보여 준다. 원본 전체 XML을 새로 구성하거나 텍스트 노드를 순서대로 덮어쓰지 않는다.

자동화 API 근거: 한컴 HwpAutomation의 `Open`, `SaveAs`, `RegisterModule`, `RepeatFind/FindReplace`, `InsertText/InsertText`, `StyleEx/Style`. [한컴 공식 문서](https://developer.hancom.com/hwpautomation).

## 문장과 지문 상자의 간격

발문 다음에 지문 테두리가 너무 붙으면 첫 지문 상자 앞에 원래 본문 스타일의 빈 문단 하나를 넣는다. 같은 지문 상자의 각 줄 사이에는 빈 줄을 넣지 않는다. 상자·표·본문의 기존 폭·글꼴·문단 정의를 바꾸지 않고 출력에서 간격을 확인한다. 지정된 학교 양식이 별도 간격을 요구하면 그 기준을 우선한다.

수식·코드·그림의 입력과 교사 제공 PDF 부분 캡처는 [수식·코드와 PDF 그림](수식-코드와-PDF그림.md)을 읽는다. 캡처에는 Windows 내장 기능만 쓰며 다른 개인 스킬·외부 서비스·도형 엔진이 필요하지 않다.

교사용 양식과 여러 조건·코드의 상자 조판은 [해설·조건 상자와 코드](해설-조건상자와-코드.md)를 따른다. `body.boxes`가 있을 때는 설치된 Python의 표준 라이브러리로 상자만 복제한 뒤 다시 한글에서 출력한다.
