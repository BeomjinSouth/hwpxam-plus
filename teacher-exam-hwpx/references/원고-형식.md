# 검사 도구의 원고 형식

문항을 만들 때 이 형식으로 원고와 검토를 함께 저장한다. 도구는 실제 풀이의 정확성을 판정하지 않으므로 먼저 학생용을 풀고 근거를 작성한다.

최상위는 `title`, `subject`, `curriculum_status`, `total_points`, `passages`, `items`, `cross_item_review`를 둔다. `passages`는 공통 지문 목록이며 각 항목은 `title`과 `text`를 갖는다. 문항별 독립 지문은 `stem`에 함께 쓸 수 있다. `cross_item_review`에는 실제로 비교한 문항 간 중복과 답 노출을 적는다.

모든 문항에 다음 필드를 넣는다.

| 키 | 값 |
|---|---|
| id | 문항 고유 ID. 예: MC1, E1 |
| type | 선택형은 mc, 서답형은 essay |
| points | 양수 배점 |
| stem | 학생용 물음과 필요한 자료 |
| objective | 학생이 해야 하는 구체적 판단 |
| derivation | 원문 자료·조건으로 답을 얻는 실제 추론 |
| shortest_solution | 찾은 가장 짧은 타당한 풀이 |
| source_status | 창작/재사용 구분, 확인한 자료·위치와 미확인 범위 |
| answer | 선택형은 정답 선택지 ID 배열, 서답형은 인정 답안 문자열 |
| shortcut_tests | id 1~7의 우회 점검. 각 항목에 result와 실제 evidence |

선택형에는 `choices: [{"id":"1","text":"선택지 문장"}, ...]`와 `option_review`를 넣는다. 검토에는 모든 선택지 ID마다 `satisfies_prompt`를 JSON 논리값 `true` 또는 `false`로 쓰고 `reason`을 적는다. 정답 조건에 해당하지 않는 보기에는 `misconception`으로 진단할 오개념·오독을 적는다. `selection`은 기본 `single`이며 여러 답을 고르는 문항만 `multiple`로 명시한다.

서답형에는 `rubric: [{"criterion":"평가 요소","points":배점,"evidence":"인정 근거"}, ...]`를 넣는다. 합계는 문항 배점과 맞춘다. `answer_only`, `alternative_answers`, `partial_combinations`에 답만 쓴 경우, 동치 표현·대안 풀이, 일부 요소만 맞은 조합을 각각 구체적으로 적는다.

우회 점검의 `result`는 `blocked`, `found`, `not_applicable`이다. `found`가 해결되지 않으면 확정 원고 검사에서 실패한다. 자료가 없어도 풀리는 보기를 보조 문항으로 낮춘 경우에만 `assessment_role: "support"`와 `resolution: {"decision":"reclassified","new_level":"중","reason":"실제로 확인한 지름길과 하향 이유"}`를 기록한다. 이 문항은 중상 도전 문항 수에 포함하지 않는다. `not_applicable`에는 해당하지 않는 이유를 적고, 선택형의 점검 1·2는 생략하지 않는다. 검사 통과를 위해 근거 없이 `blocked`를 채우지 않는다.

```text
python scripts/exam_check.py check 원고.json
python scripts/exam_check.py packet 원고.json 학생용-독립검토.md
```

학생용 검토 파일에는 문항·선택지·공통 지문만 포함되며 정답·해설·설계 의도는 포함되지 않는다. 실제 HWPX/PDF에서는 원고의 조건·지문·물음·보기와 동일한지 문항별로 다시 대조한다.

## 한글 채움 명세의 혼합 입력

문항 원고와 별도로 양식용 채움 JSON을 만든다. 각 block은 한 문단이며 원래 양식의 `style_id`를 명시한다. `text`는 대조용 원문이다. 일반 문장과 편집 가능한 수식은 `runs`의 `text`·`equation` 조각으로 순서대로 넣는다. `equation`에는 `script`와 `base_pt`가 필요하다. 코드는 한 줄씩 `code: true`를 지정하고 공백을 보존한다. 그림은 별도 block의 `image`에 확인한 `path`·`sha256`·실제 `width_mm`·`height_mm`를 넣는다. 그림과 runs를 한 block에 섞지 않는다.

발문과 지문 상자가 맞닿으면 첫 지문 상자 앞에 기존 본문 스타일의 `text: ""` block을 넣는다. 양식의 전체 문단 간격이나 표 여백을 일괄 변경하지 않는다. 자세한 JSON과 PDF 부분 캡처 절차는 [수식·코드와 PDF 그림](수식-코드와-PDF그림.md)을 따른다.

실제 조건·코드 상자는 연속 문단의 `box_id`와 `body.boxes`로 지정한다. 자세한 명세는 [해설·조건 상자와 코드](해설-조건상자와-코드.md)를 따른다.

## 교과서 정리본을 쓴 원고

정리본을 참고했으면 원고 최상위에 `textbook_reference: [{"id": "정리본 id", "units": ["Ⅲ"]}]`를 둔다. 이때 모든 문항에 `textbook_use`를 넣는다.

| 키 | 값 |
|---|---|
| terms_checked | 교과서 표기와 대조한 용어·기호 목록 |
| definitions_applied | 풀이에 쓰이는 교과서 정의·성질과 쪽(예: "기울기, 교과서 112쪽"). 없으면 빈 배열 |
| scope_check | 범위 메모와 대조한 결과(예: "y축 방향 평행이동만 사용") |
| design_origin | 문항을 무엇에서 설계했는지(평가목표·새 상황) |
| differs_from_textbook | 비슷한 교과서 예제·문제와 무엇이 다른지 |
| overlap_resolution | (선택) overlap 검사에서 겹침이 나왔지만 의도한 인용일 때 그 이유 |

교과서 지문을 원문 그대로 제시문으로 쓰면 그 지문에 `textbook_passage: true`를 표시한다. `passages` 항목이면 그 항목에, `presentation.student`의 passage 문단이면 그 문단에 둔다. overlap 검사는 표시한 지문을 겹침 계산에서 뺀다.

```text
python -B scripts/textbook_lookup.py find --subject 수학 --grade 중2
python -B scripts/exam_check.py overlap 원고.json --digest "<원문.json 경로>"
```
