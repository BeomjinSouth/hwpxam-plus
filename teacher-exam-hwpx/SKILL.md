# 전교과 시험지 제작

현재 요청과 교사가 제공한 평가계획·성취기준·교과서·양식을 우선한다. 이 폴더 안의 지침과 도구, 교사 PC에 저장된 학교명과 교과서 정리본만 사용한다. 다른 스킬·플러그인·유료 API·개인 메모리·특정 학교 파일을 전제로 삼지 않는다. 학교명과 정리본은 `~/.teacher-exam-hwpx/`(환경변수 `TEACHER_EXAM_HOME`이 있으면 그 폴더)에 있으며, 스킬을 다시 설치해도 지워지지 않는다. 교과서 정리본은 함께 설치되는 textbook-digest 스킬이 만든다.

## 학교명은 처음 한 번만 묻는다

제작을 시작하면 `python -B scripts/school_profile.py show`로 저장된 학교명을 확인한다.

- `OK`면 저장된 이름을 쓰고 다시 묻지 않는다.
- `MISSING`이면 교사의 요청·평가계획에서 교사가 직접 밝힌 학교명을 찾는다. 공유받은 양식에 인쇄된 학교명은 교사의 학교라고 단정하지 않는다. 찾지 못하면 다른 누락 정보와 함께 한 번만 묻는다. "처음 사용하시네요. 시험지에 넣을 학교명을 알려 주세요. (예: 길동중)"
- 받은 이름은 `python -B scripts/school_profile.py set --name "길동중" --official "길동중학교"`로 저장한다. 정식 이름은 줄임말에서 분명할 때만 채우고(길동중→길동중학교, 길동고→길동고등학교), 애매하면 교사에게 확인한다. 저장한 뒤 보고에 "학교명 '길동중학교'를 저장해 다음부터 자동으로 씁니다."라고 적는다.
- 교사가 학교명을 바꿔 달라고 하면 `--replace`를 붙여 다시 저장한다.

양식에 다른 학교 이름이 인쇄돼 있으면(예: 공유받은 양식의 '한빛중학교', 글자 사이를 띄운 '한 빛 중 학 교') 원고의 `metadata`로 모든 위치를 저장된 학교명으로 바꾼다. 원래의 띄어쓰기 모양과 글꼴은 그대로 두고 글자만 바꾼다. 글자 수가 달라 고정 칸을 넘치면 글자 사이 띄어쓰기만 줄여 맞춘다. 양식에 학교명 자리가 없으면 새로 만들지 않는다.

## 한 요청을 끝까지 실행한다

시험지 제작 요청을 받으면 [처음부터 끝까지 실행](references/처음부터-끝까지-실행.md)을 읽고 `scripts/exam_pipeline.py`의 prepare → run → render → finalize 순서로 끝낸다. AI가 양식 위치표와 검토한 원고를 작성한다. 교사에게 실행 스크립트나 교사용 기준본을 따로 준비하게 하지 않는다.

이전 대화·이미 만든 문항·작업 폴더의 보조 코드를 요구하지 않는다. 새 요청의 원본에서 기준본을 준비하고 같은 원고에서 학생용·교사용을 함께 만든다. 한 번 호출한다는 것은 내부의 내용 검토·배치 수정까지 AI가 수행한다는 뜻이다. 검토 중 원고나 배치가 달라지면 해당 입력을 고쳐 다시 출력한다. PDF를 직접 수정하거나 문항별 임시 제작 코드를 만들어 부족한 스킬 기능을 대신하지 않는다. 도구의 실제 결함이면 확인한 실패를 보고하고 스킬 도구 자체를 수정·검증한 뒤 재실행한다.

조건·자료·코드는 원고의 문단 종류로 구별하여 실제 상자에 넣고, 상자 앞 빈 문단과 코드 제목 폭을 자동으로 확보한다. 교사용에는 정답·해설·보기 판단·채점·인정 답안·부분점수를 싣는다. 원고의 내부 ID·출처 확인 메모·제작 안내는 검증 기록에 남긴다.

모든 쪽의 실제 PDF 확인과 현재 파일 해시에 연결된 최종 검수 기록까지가 완료 조건이다. 출력 성공만으로 끝내지 않는다. HWP/HWPX 원본·최종 파일의 변경 여부, 문항별 재풀이와 미확인 범위를 함께 기록한다.

고정 영역은 원래 양식의 실제 배치를 기준으로 보존한다. 시험정보만 바꾼 비교용 PDF와 최종본이 같다는 사실만으로 원본 보존을 판정하지 않는다. 준비 도구가 기록한 표시 높이 유지와 본문 앞 줄 위치 검사를 통과하고, 원본에서 안내·저작권·제목 영역이 다른 쪽으로 이동하지 않았는지 실제 PDF로 확인한다.

## 요청을 나누고 필요한 자료를 읽는다

- 문항을 새로 만들거나 조건·보기·물음을 바꿀 때에는 [문항 제작 요령과 검토](references/문항-설계와-검토.md)를 먼저 읽는다. 중상 난도 요청에는 그 문서의 교과별 설계 예와 탈락 기준을 함께 적용한다.
- 교과서 정리본이 있으면 [교과서 정리본 활용](references/교과서-정리본-활용.md)을 읽고 그 순서를 지킨다. 설계는 범위 카드만 보고 하고, 원문은 검산할 때 연다. 정리본이 없는데 교사가 교과서 PDF를 주면 textbook-digest 스킬로 출제 범위를 먼저 정리할지 묻는다.
- 확정 문항을 조판만 할 때에는 그 내용을 보존한다. 내용 수정이 필요해지면 문항 설계·검토로 돌아간다.
- HWP/HWPX를 다룰 때에는 [양식 보존과 실행](references/양식-보존과-실행.md)을 읽는다.
- 숫자·단위·수식·알고리즘·코드·PDF 그림을 넣을 때에는 [수식·코드와 PDF 그림](references/수식-코드와-PDF그림.md)을 읽는다. 제공 PDF의 그림이 필요하면 AI가 쪽을 찾아 필요한 영역만 발췌하고 원본·캡처·문항을 대조한다.
- 교사용 해설, 여러 작성 조건이나 코드를 조판할 때에는 [해설·조건 상자와 코드](references/해설-조건상자와-코드.md)를 읽는다. 교사용 구성과 학생용 제작 안내 제거, 원본 상자 복제를 함께 확인한다.
- 전달 전에는 [검수와 전달](references/검수와-전달.md)을 읽는다.

학년·교과·교육과정·출제 범위·문항 유형과 수·배점·시험 시간 중 이미 받은 정보를 재사용한다. 허용 풀이와 평가 내용이 달라지는 누락만 모아서 묻는다. 시행 날짜·출제자·성취기준 코드·교과서 쪽수를 추측하여 채우지 않는다. 예시 검증이면 가상의 시행 정보를 명시해 진행할 수 있다.

## 문항을 설계하고 검토한다

1. 각 문항에서 학생이 실제로 해야 할 판단과 답의 근거를 적고, 전체 내용별 문항 수와 배점을 맞춘다. 중상 이상 문항은 다른 추론 구조 두 개를 비교해 채택한다. 모든 문항을 복잡하게 만들지는 않는다.
2. 답과 타당한 추론을 먼저 구성하고 그 추론이 필요한 조건·자료·물음을 만든다. 용어를 어렵게 하거나 지문과 계산을 늘린 것을 난도 상승으로 보지 않는다.
3. 각 오답이 나오는 오개념·오독·추론 누락을 적는다. 모든 보기를 질문의 정답 조건에 맞춰 판정한다. 긍정·부정 발문과 복수 선택을 구별한다.
4. 학생용만 보고 다시 푼다. 단서만으로 정답 고르기, 상식만으로 풀기, 장식 조건, 교육과정 밖 지식, 다른 문항의 답 노출을 실제로 시험한다. 목표 판단이 사라지는 우회로는 고친다. 목표에 맞는 정당한 대안 풀이를 길이가 짧다는 이유로 탈락시키지 않는다.
5. 별도 검토 도구나 에이전트가 허용되면 정답·의도·해설을 뺀 학생용만 먼저 주어 풀게 한다. 답을 기록한 뒤 교사용과 대조한다. 독립 실행이 불가능하면 자체 재검토를 하고 ‘독립 검토 미완료’로 남긴다.
6. 서답형은 근거·인정 답안·단계별 부분점수·동치 답안·답만 쓴 경우·오류의 중복 감점을 명확히 한다. 여러 요소를 요구하면 일부만 맞은 조합의 처리도 정한다.
7. 교과서 정리본을 썼으면 용어·정의·범위를 원문과 대조하고 `scripts/exam_check.py overlap`으로 교과서 문장·예제와의 겹침을 검사한다.

원고·설계표·모든 보기의 판단·서답형 채점기준·출처 및 미확인 범위를 작업 폴더에 남긴다. [원고 형식](references/원고-형식.md)에 따라 `scripts/exam_check.py check`로 기록 누락·배점·정답 연결을 검사한다. 통과가 교과 내용의 정확성이나 난도를 증명하지 않는다. 초안 요청에는 미검증 상태를 밝혀 제공하고 통과 기록을 만들어 내지 않는다.

## 한글 양식에 내용만 채운다

제공 파일을 읽고 해시를 기록한 뒤 원본과 다른 이름으로 복제한다. 용지·방향·여백·다단·표와 셀·머리말·꼬리말·결재란·글꼴·자동 번호·선택지 모양을 유지한다. 현재 요청에서 바꿀 시험 정보와 내용 자리만 정한다.

기존 양식을 새 문서·HTML·Markdown 변환으로 다시 만들지 않는다. 새 스타일 ID나 학교 양식을 추측하여 대입하지 않는다. 문항 본문에 기존 스타일을 재사용할 수 있는지 확인한다. 채울 곳이 불분명하면 양식의 현재 내용을 보여 주고 위치만 확인한다. 양식이 없으면 교사의 양식을 요청하며 임의의 학교 서식으로 대체하지 않는다.

Windows에서는 `scripts/hancom_fill.ps1`이 새 한글 자동화 객체에서 원본의 복사본을 열고, 승인한 문자열·지정 본문 위치만 바꾼다. 제공 양식의 자동 문항 번호와 선택지 스타일을 실제 이름·ID로 읽어 적용한다. 이 도구가 지원하지 않는 개체·양식은 네이티브 편집으로 처리 가능한 범위부터 확인한다. 원문이나 잠긴 개체를 삭제해 억지로 통과시키지 않는다.

본문 길이 때문에 기존 고정 영역이 달라지면 문항의 의미를 유지한 문장 정리와 본문 배치를 먼저 조정한다. 글꼴·여백·표 크기 변경이나 문항 수 변경이 필요하면 그 차이를 교사에게 알린다. 교사가 승인하지 않은 서식 변화가 남으면 양식 보존 검사를 통과한 것으로 보고하지 않는다.

도형을 생성하지 않는다. 교사가 준 그림·도표·사진은 원본 상태로 보존하고 내용과 출처를 검토한다. 교과상 필요한 편집 가능한 수식·화학식·악보 등의 개체는 해당 프로그램이 지원하는 방식으로 입력한다. 일반 텍스트나 이미지로 임의 대체하지 않는다. 지원하지 않으면 해당 항목을 보류하고 이유를 알린다.

PDF의 그림은 필요한 부분을 자르는 방식으로 사용하며 의미를 바꾸어 다시 그리지 않는다. 문항·해설·다른 그림을 함께 캡처하지 않는다. 그림이 평가하는 정보라면 그림을 보지 않고도 답이 나오는지 별도로 시험한다.

## 확인한 범위만 전달한다

최종 HWPX를 한글에서 직접 PDF로 내보내고 학생용·교사용의 모든 쪽을 본다. 파일 해시, 원고와 실제 인쇄 문항의 일치, 선택지 번호, 정답표, 채점기준, 잘림·겹침·빈 쪽·풀이 공간·기존 문항·메모·정답 노출을 확인한다. PDF를 별도로 재작성해 HWPX 검증 증거로 쓰지 않는다.

학생용 HWPX/PDF와 교사용 정답·해설·채점기준 HWPX/PDF를 분리한다. 같은 문항 원본에서 두 문서를 만들고, 보기 순서가 바뀌면 답 번호와 해설을 함께 갱신한다. 파일을 수정하면 이전 해시의 검수는 현재 파일에 재사용하지 않는다.

한글이나 출력 도구가 없으면 원고와 가능한 구조 검사까지 진행한다. 실제 열기·인쇄·독립 검토·교육과정 대조 중 미확인 사항을 명시하고, ‘바로 시행 가능’이라고 말하지 않는다. 설치와 문서 제작 요청을 외부 전송·배포 권한으로 확대하지 않는다.
